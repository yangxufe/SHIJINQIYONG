# 家庭菜谱、分类与网上教程收藏设计

用户新增需求（2026-09-25）：按当前可用食材排序并分类；家庭成员可录入自己的菜谱，或搜索视频、文字、图片教程并保存；家庭录入内容只对本家庭成员可见。

## 方案取舍

1. **推荐：本机结构化菜谱 + 外部教程链接。**家庭成员录入标题、食材、做法、分类、标签和来源；网页提供用户主动点击的外部搜索入口，选中教程后复制链接并填写摘要。菜谱和笔记保存在本机 SQLite，断网仍能查看文字内容；原网站视频/图片需联网打开。没有服务器抓取、嵌入、自动转载或在线 AI。
2. 服务器自动抓取视频、文章和图片：来源规则各异，内容可能失效或受版权限制，还增加服务器出站和不可信 HTML 处理；当前不选。
3. 原视频文件上传：可彻底本地保存，但大文件会改变上传、备份、容量和恶意文件防护方案。已向用户询问，取得选择前不将远程视频自动下载到本机。

## 数据与权限

新增家庭菜谱表；本项目只有一个家庭，成员账号和管理员账号共享访问，匿名及没有家庭角色的账号不可读写。记录创建人、标题、食材名列表、步骤、分类、最多若干标签、教程类型、HTTPS 原链接、备注、创建时间和编辑版本。内置 JSON 菜谱继续随源码提供。家庭自建菜谱使用独立 ID，不与内置 ID 冲突。普通表单走 Django 会话和 CSRF；输入长度、URL scheme、重复字段与分类/标签都在服务端校验。模板自动转义；外链新窗口打开，`noopener noreferrer`。

## 匹配与页面

匹配只读取当前真实可用批次，复用家庭时区与危险批次排除规则。已知别名用显式映射，其他食材仅精确名称匹配。默认按可匹配食材比例、匹配数和稳定顺序排列；页面可按分类过滤、按标题/标签搜索，并显示食材是否齐全。打开或保存菜谱不动库存；做饭仍填写每批次实际用量并复用阶段 05 的事务扣减、版本检查、持久幂等记录与流水。分类与标签不影响库存安全判断。

## 搜索与测试

外部搜索仅由成员点击后在浏览器打开，不把家庭库存自动提交给搜索网站。用户核对网页后自行填写链接和需要保存的内容；本机不声称拥有外站内容。测试覆盖匿名/非成员拒绝、CSRF、创建与编辑、分类标签、链接校验、搜索参数编码、可用批次排序、XSS 转义、家庭成员可读、原库存扣减回归和迁移。上线前做私有 SQLite 备份，迁移后跑完整套件，并用可信根 CA 探测当前 LAN 服务。真实手机流程需现场验收。
