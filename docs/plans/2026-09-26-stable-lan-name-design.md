# 固定局域网网址设计

日期：2026-09-26。此方案已按用户要求暂停，当前运行方式回到 `https://192.168.1.220:8443/`；以下内容仅作待续设计记录。原实验域名漏写“其”的拼音 `qi`，若以后继续应使用完整名称 `shijinqiyong.local` 并重新验收。用户要求 Android 手机与电脑位于同一可信 Wi-Fi 时使用不随 DHCP 地址变化的网址；新 Wi-Fi 先由用户确认。已确认 `White Whale` 为可信网络。应用仍仅用于单家庭局域网，不设公网入口。

## 选择

若以后恢复此方案，拟用固定网址 `https://shijinqiyong.local:8443/`。mDNS 在当前局域网把名称解析为电脑的 WLAN IPv4 地址；Caddy 用原有内部 CA 为该主机名签发证书，再转发到只监听 loopback 的 Waitress。Django 只接受该精确 Host/Origin。Android 的系统解析器支持 `.local` mDNS；实际手机浏览器还需现场验证。此前电脑上的临时 Zeroconf 试验使用了缺 `qi` 的旧名称，解析到 `192.168.1.220`；这不构成完整名称或 Android 手机的验证。

## 网络访问范围

Windows 防火墙规则仅放行 Caddy 程序、WLAN、TCP 8443、本机当前 IPv4 和同一子网。后台网络守护脚本匹配已确认的 Wi-Fi 名称及 AP BSSID；未知网络时禁用规则并撤销 mDNS 发布。新网络需用户再次确认后加入受保护的可信列表。Caddy 在 Windows 上的监听记录显示为 `::`，但已验证可从当前 IPv4 接入；实际入站范围由限定当前 IPv4 的 Windows 防火墙规则控制。Waitress、Ollama 继续只监听 loopback。已确认网络在 DHCP 地址变化后自动更新防火墙的本机地址，不靠静态 IP。

受保护的守护脚本和网络列表安装到 `C:\Program Files\ShiJinQiYong\NetworkGuard`，仅管理员/SYSTEM 可写，计划任务以系统身份运行；项目目录中的普通用户可编辑文件不会被高权限任务动态执行。名称发布脚本以当前用户运行，只读取守护脚本写的当前可信地址。守护失效时，入口不能被视为已正确限制；验收需包含未知网络的关闭检查。

## 其他方案及取舍

- 每个路由器配置相同的本地 DNS 名称：无需电脑 mDNS 发布，但每换一台路由器都要修改其 DNS；用户频繁换网，不作为首选，也不擅自改路由器。
- 每个网络都安排相同的静态 IP：不同子网和 DHCP 分配下不可靠，无法保证网址不变。
- VPN 或公网域名：超出用户明确的同一可信 Wi-Fi 范围，增加外部依赖；本次不引入。

## 验证与限制

已验证 Caddy 配置、严格 CA 校验下的电脑 HTTPS、当前网络守护状态、电脑 mDNS 解析和完整 Django 回归。未知网络用合成名单执行守护逻辑的只读检查；实际换网、DHCP 换地址、整机重启与 Android 手机访问仍未执行。Android 手机需在可信 Wi-Fi 上确认名称可解析、证书无警告、登录与采购流程可用；本机请求不能代替这些结果。新 Wi-Fi 的 AP BSSID 可能随路由器/mesh 节点变化，需要确认后补充；同名伪造网络不能仅凭 SSID 判断可信。根证书仍须在手机上安装并启用信任。若系统守护任务异常退出，已经启用的防火墙规则不会自动过期，需检查任务状态后再把未知网络隔离视为已验收。
