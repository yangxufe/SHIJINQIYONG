# 阶段 05：本地菜谱设计

用户在阶段 04 手机验证后启动阶段 05。目标是用真实可用库存找菜谱，并在成员确认实际用量后扣减批次和记录流水。既有架构规定同源 Django 单体、原生页面、本地 JSON 菜谱和显式食材别名。

## 选择

采用版本化 JSON 存少量家常菜与别名，服务端按精确名称映射库存批次。这样无需新数据库表、管理员菜谱编辑界面或运行时网络。数据库维护菜谱会增加权限与迁移面；让本机模型自由生成做法或推断用量会使匹配和扣减难以复核。本阶段选择确定的本地数据，不调用模型参与数量决策。

## 数据流

`/recipes/` 从本地目录载入菜谱，读取库存中在库、储存已核对、数量大于零、包装日期未过的批次。页面显示每道菜找到和缺少哪些食材，但不宣称数量够用。详情页列出做法与对应批次。查看与选择均为只读。成员为每种食材填写至少一个批次的实际用量，再提交。服务端核对批次是否属于菜谱食材，调用已有 `apply_action(kind="cook")`，让版本检查、短事务、幂等结果、库存更新与流水一同提交。失败时保留输入；同一编号重试仍由库存服务返回原结果。

## 边界与验证

不换算单位、不猜测用量，不推荐疑似变质、储存待核对或包装日期已过的批次。菜谱做法只是参考，不给出食物安全保证。测试覆盖别名、排除规则、只读浏览、CSRF、真实扣减、幂等重放、旧版本回滚和无关批次拒绝。真实手机触控与家庭菜谱偏好由用户验收。
