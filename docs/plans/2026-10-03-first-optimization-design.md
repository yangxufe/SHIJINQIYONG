# 第一次优化与 YOLO 实施设计

依据用户 2026-10-03 授权及所附 6 项问题清单，在现有项目内增量修改。

1. 未登录首页展示本机花体字体标题及登录/注册；注册由管理员生成 24 小时一次性邀请码。使用 Django UserCreationForm、签名、密码校验与短事务，不开放陌生人自助加入家庭。普通成员可看家庭设置入口，但只有管理员可发邀请与改家庭配置。
2. 今天保持常驻，固定增加“添加菜品”，连接已有冰箱录入；清单写明具体内容后续确定，因此不添加未经确定的新业务。
3. 复用统一页头，所有应用页面显示右上角小字家庭设置和退出登录，正常文档流适配小屏，退出仍为 CSRF POST。
4. 相机 capture 和相册无 capture 使用独立隐藏文件输入，只有明确按钮点击触发，不显示文件数量。YOLO 结果点击确认后写名称，保存前不改库存。
5. 个性化入口改为“填写菜谱要求”，下一页结构化条件直接提交生成任务；不经过旧解释/候选中间页面。原自然语言解释路径保留兼容；模型未配置时诚实提示本地匹配降级，不产生假生成结果。
6. 按食材匹配区及列表 API 过滤匹配数为 0 的条目；只有真实合格库存进入匹配。不把尚未采购入库或待核对库存当成食材。
7. 识别后端移除 qwen3-vl 与 Ollama 调用。选择官方 YOLO-World v2 小模型，在构建时固定 32 类食材词表，导出 640 ONNX；线上仅 ONNX Runtime CPU 两线程、单并发，不调用文本模型、不外传照片、不执行 .pt。自定义专用训练权重后续可通过相同格式替换。
8. 通用 COCO YOLO 的食材类别有限；YOLO-World 可固定更多食材类别而无需在应用里加载大型文本模型。开放词表不是专门的家庭食材训练，肉类相似、包装文字、遮挡仍需人工核对。包装不透明时只能手工填写，不能冒充 OCR。
