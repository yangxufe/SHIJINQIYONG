# 第三次优化实施设计

依据第三次 DOCX 的四组要求，以及用户追加的“保质期由用户用按钮切换填写方式”。回退基线 516f80a，标记 rollback-before-third-optimization-20261005；按现有停止流程完成私有备份 household-20261005-195704-1f92a1b9（0 附件），随后恢复 Waitress。

采用独立的添加页 /inventory/ 与食材列表 /inventory/list/，共享原库存服务、API 和表单增强脚本。单页隐藏列表会使入口和返回含糊，复制另一套库存服务会增加一致性风险；独立模板能保留搜索、分页、编辑、用量、丢弃和原版本/幂等处理。

- 首页按添加菜品、食材列表、查看菜谱、采购计划排序；食材列表移动原批次卡片与搜索，保存/编辑/动作后返回列表。旧添加页带 q/page 的搜索地址兼容跳转到新列表。
- 添加页只保留清单所列七组输入，四项必填有星号；识别和提示按原文精简。去掉更多信息，原储存/疑似变质/手动优先等编辑能力保留在批次编辑页。新录入仍默认储存待核对，不能由照片或填写日期自动认定可用。
- 保质期提供截止日期/天数两个按钮式单选项；天数模式需要显式起算日期，截止日期=起算日期+天数，不自动使用采购日期。两种方式均由服务端转换成原 package_date/package_date_status 并经过原 create_lot；不新增表或迁移。天数和起算日期只用于本次输入，保存后列表显示最终截止日期，日后编辑仍编辑该日期。未填写保质期保持未知。数量、流水、事务与幂等机制保持原实现。
- 菜谱筛选固定荤菜、素菜、汤羹、其他，保留全部分类重置项。内置菜谱用明确 ID 映射；家庭菜谱的四类名称直接映射，已有清淡素菜映射素菜，其他自定义分类归其他，原分类/标签/ID 保留。旧分类查询仍可精确筛选；分类只是浏览分组，不代替过敏/禁食或数量规则。列表页链接统一为现有正文色、无下划线，保留按钮、焦点和点击语义。
- 采购页只对该页 select 使用本地箭头，固定高度及右侧留白；勾选确认独占一行，下一行加入清单。库存说明按清单精简并链接新食材列表，保留原可用批次过滤和采购唯一入库服务。
- 验证两种保质期（闰日/缺起算日期/非法范围/未知/重试冲突）、HTML 与 JSON 一致、列表权限/搜索/编辑/动作、旧数据保留、分类与不安全批次排除、采购防重复；真实浏览器用独立合成库测试按钮、切换、四入口及 320/390/1280 宽度。完成后更新进度与交接、同步 GitHub。手机证书信任按用户要求暂缓，不改变 CA 或网络。
