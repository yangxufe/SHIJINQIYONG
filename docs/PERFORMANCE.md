# 阶段 07A 性能复测

日期：2026-09-26。测量使用迁移后私有备份恢复出的**独立副本**，没有向生产库存写入测试食材。脚本 `work/stage07a_performance_probe.py` 通过 Django 测试客户端、生产设置和已登录成员调用页面；每个读页面预热一次后取 30 次，库存创建取 20 次。单位为毫秒，p95 是样本排序后的第 95 百分位。此测量不包括手机、Wi-Fi、Caddy 和 TLS 开销。

| 操作 | 次数 | p95 |
|---|---:|---:|
| 冰箱 `/inventory/` | 30 | 7.4 |
| 做什么 `/recipes/` | 30 | 8.0 |
| 工作台候选结果 | 30 | 120.4 |
| 采购 `/shopping/` | 30 | 9.2 |
| 隔离副本创建库存批次 | 20 | 11.0 |

新增的并发自动化测试让模拟模型请求停在等待态，同时在另一个连接完成库存写入；写入在 1.5 秒断言期限内完成。它验证模型等待没有持有数据库写事务或占用普通请求执行路径，**不是**真实供应商慢请求的延迟、计费或生产负载数据。工作进程默认未启动；真实模型耗时、排队量、Caddy 端到端 p95、手机交互时间均未测得。现有第 07 阶段普通读写指标不能以生成耗时代替。

复测条件：配置真实模型后，在明确授权的家庭网络上用慢请求和排队任务同时测普通冰箱、采购读写与候选页；单列模型耗时、失败和队列等待。手机证书无警告和采购流程通过前，不把本机数字当作发布验收。

## YOLO 替换后的真实并行测量（2026-10-03）

环境为当前 Windows 开发机、Python 3.10.20、Django 5.2.17、ONNX Runtime 1.23.2、YOLO-World v2 CPU 两线程；模型构建识别的 CPU 为 Intel Core Ultra 9 386H。独立 work/yolo-performance-* 文件 SQLite 与合成账号；Django test Client 直接调用，未将生产数据用于测试。

预热真实 ONNX 后，一线程连续 12 次公开 COCO 样本识别，主线程同步 30 次库存 API 读取和 30 次创建；全部 30 轮发生在识别线程存活期间。全部响应按预期 200/201，没有错误、负库存或锁错误。识别没有使用模拟提供者。

| 请求 | 次数 | p95 | 最大 |
|---|---:|---:|---:|
| 库存读取 | 30 | 27.5 ms | 63.8 ms |
| 创建批次（含事务与流水） | 30 | 23.6 ms | 27.4 ms |
| 真实 YOLO 照片识别 | 12 | 362.9 ms | 362.9 ms |

首次会话加载与图片推理约 1.8–2.0 秒，后续公开图约 0.29–0.36 秒；这些是当前电脑后端样本，不是模型准确率、不含 Waitress/Caddy/网络传输，也不是 Android LCP/INP 或家庭 HTTPS p95。单识别槽忙时明确 503，不占满其他请求线程；数据库写事务不包住模型推理。尚未测手机 HTTPS 或另一台 Mac 的 CPU 延迟。
