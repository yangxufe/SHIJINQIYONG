# 食尽其用

Windows 已安装主机的日常启动及新 Windows 电脑的独立安装见 [Windows 启动教程](docs/WINDOWS.md)；macOS 见 [Mac 安装与局域网访问说明](docs/MACOS.md)。新电脑会建立**自己的**数据库、成员账号与 HTTPS 证书；源码仓库不含原电脑的家庭数据或证书私钥。

中文、手机优先的单家庭局域网食材管理应用。“做什么”增加了按实际数量和条件推荐的菜谱工作台、详细教程与可选生成任务；成员确认实际用量后才扣减库存并记录流水。冰箱录入支持本机拍照识别；采购可核对现有库存、标记买到并按实际数量唯一入库。阶段 07A 的真实模型未联调，Android 仍报告证书警告。

**当前入口：**`https://192.168.110.146:8443/`，仅在此前确认的家庭 Wi-Fi 同网段可用。固定 `.local` 名称实验已暂停。手机出现证书警告时不要继续登录；以下各阶段地址只作为历史记录。

## 本机运行

安装依赖：`.\.venv\Scripts\python.exe -m pip install -r requirements.lock`（隔离环境已经创建）。生产配置由 `data/runtime.env` 提供；首次初始化运行 `scripts/initialize_runtime.ps1`，已有配置不会被覆盖。

- 检查：`& scripts/manage_prod.ps1 check`
- 迁移：`& scripts/manage_prod.ps1 migrate --noinput`
- 收集静态文件：`& scripts/manage_prod.ps1 collectstatic --noinput`
- 启动 Waitress 登录任务：`Start-ScheduledTask ShiJinQiYong-Waitress`（只监听 `127.0.0.1:8000`）
- 启动本机识别任务：`Start-ScheduledTask ShiJinQiYong-Ollama`（只监听 `127.0.0.1:11434`）
- 当前 Caddy 服务在已确认的 “White Whale” Wi-Fi 上以 IP 地址开放；固定名称方案已暂停，名称发布和自动换网守护任务均已停用。

本机交互创建账号，不在命令行输入密码：

- 管理员：`& scripts/manage_prod.ps1 manage_member create <用户名> --role admin`
- 成员：`& scripts/manage_prod.ps1 manage_member create <用户名> --role member`
- 修改密码：`& scripts/manage_prod.ps1 manage_member password <用户名>`
- 禁用/启用：`& scripts/manage_prod.ps1 manage_member disable <用户名>` / `enable <用户名>`
- 解锁：`& scripts/manage_prod.ps1 manage_member unlock --username <用户名>` 或 `--ip <实际来源IP>`；同时指定会分别清除这两类锁定记录。

密码输入不会回显，并经过 Django 密码验证。禁用或改密会撤销该账号的现有服务器会话。没有默认账号、公开注册、Django admin 或远程恢复入口。

阶段 07 的历史入口为 `https://192.168.1.220:8443/`，仅供手机与电脑连接同一已确认家庭 Wi-Fi 时使用。Caddy 以 `LocalService` 运行，监听当前 WLAN 地址，防火墙只允许该地址、WLAN 与同一子网。网络地址变化时不会自动切换，需先确认新网络再调整；不要在未知网络上直接开放。Waitress 和本机识别服务仍只监听本机。手机必须信任家庭根 CA，证书警告时不要登录，具体见 `docs/HANDOFF.md`。

登录后从首页进入“冰箱与批次”可录入批次并记录实际用量、丢弃或校正。数量以批次单位输入，最多三位小数；校正填写**校正后的剩余量**，说明必填。储存待核对、疑似变质或包装日期已过的批次不能登记为做饭/直接食用。表单提交后才写入；若显示“结果待核对”，在原页面用原请求编号重试，不新建编号。接口字段与状态见 `docs/API.md`。

新增批次的常用字段直接显示，日期、批次名和优先顺序放在“更多信息”。手机上可拍一件散装食材或一件包装，已安装的本机 Ollama `qwen3-vl:8b` 会建议名称；照片不保存、不发给在线服务。仍须核对名称、填写实际数量与储存状况，再点“保存批次”。模型未运行或识别失败时可手工填写。一次照片只识别最主要的一种食材，真实手机准确性仍需验收。

“今天”页当前只显示标题和“计划日期是安排提醒，不是安全期限”，底部导航仍可进入其他页面；原今日库存 API 保留。底部“采购”显示清单和可用库存汇总；买到不会直接入库，确认实际数量才建立批次及流水。无 JavaScript 时，库存录入和数量表单仍可正常提交。浏览器搜索和局部更新只读取服务器记录，不建立离线库存副本。

“做什么”保留原 6 道菜谱 ID，并补充至 8 道详细参考菜谱，并允许家庭成员新增或编辑自己的菜谱、分类、标签和教程来源。默认按当前可用食材匹配比例与匹配数排序，也可按分类、名称、食材或标签筛选。页面可生成视频、文字和图片教程的外部搜索入口；成员自行选择并保存 HTTPS 链接、步骤和笔记。家庭菜谱可上传最多 6 张图片与 1 个视频（单个视频最多 200 MB），文件在私有数据目录中，只有登录的家庭成员可通过应用读取；外站教程仍需联网打开。上传的 MOV 视频在部分手机可能无法播放。

“已找到”只表示食材名称匹配，不表示份量足够。打开或保存菜谱不会扣库存。在详情页按批次填写每种食材本次实际用量并确认后，才通过原库存服务的事务、版本检查、幂等记录与流水扣减。无 JavaScript 时菜谱录入、附件上传、实际用量确认及采购流程仍可用普通表单提交。

数据库与菜谱附件必须一起备份。先运行 `& scripts/stop_waitress_for_backup.ps1`，再运行 `& scripts/manage_prod.ps1 backup_household`，最后运行 `Start-ScheduledTask ShiJinQiYong-Waitress`。备份命令会在私有 `data/backups/` 生成包含 SQLite 和所有被引用附件的完整目录并核验校验和；Waitress 正运行时会拒绝。阶段 07 已在独立目录演练恢复、清除旧会话并读取四个页面，没有覆盖生产库；整个备份目录仍需由家庭自行保存到受保护的异设备。

真实数据、运行配置、证书私钥和日志均不应加入仓库或交付包。详细环境、操作和测试证据见 `docs/ENVIRONMENT.md`、`docs/HANDOFF.md`、`docs/PROGRESS.md`。登录任务需要当前 Windows 用户登录；主机重启自动恢复尚未实测。

## 阶段 07A 菜谱工作台

进入“做什么 → 按条件找菜谱”，输入需求或选人数、食材模式、口味、器材与时间，确认系统解释后查看按当前批次数量计算的候选；可合成菜单，再单独确认采购差额或本次实际用量。严格模式缺必要调料时不会显示为完全可做；未知重量不会擅自换算。候选、生成、浏览与保存不扣库存，也不自动新增采购。家庭与个人口味设置分别维护，私人生成任务只允许本人访问。

可选生成默认关闭；配置键见 `config/recipe-provider.example.env`，单进程工作命令见 `scripts/start_recipe_worker.ps1`。缺少真实模型配置时只使用本地菜谱并明确提示。阶段 07A 自动化已通过，真实模型未联调；Android 仍提示证书警告，不能算手机安全上线。验收和运行边界见 `docs/ACCEPTANCE.md`、`docs/HANDOFF.md`。
